For two years now, I’ve been using [langchainrb](https://github.com/patterns-ai-core/langchainrb) from my friend Andrei, so what’s all the fuss about it? Needless to say, I had to try it.

### Add MCP to the mix

Have you heard about [**MCP**](https://docs.anthropic.com/en/docs/agents-and-tools/mcp)? It’s the Anthropic protocol to enrich agents by adding functionality such as Tools, Resources, Prompts. I call it the “OSI L3/L4” of LLMs, as opposed to **A2A** which is the “OSI L7” protocol (💡patent pending).

![](https://cdn-images-1.medium.com/max/898/1*ofLTW6tRh2hTYAlemTs49g.png)
*[***A2A***](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)*(*[*Agent to Agent Protocol*](https://developers.googleblog.com/en/a2a-a-new-era-of-agent-interoperability/)*) enables more sophisticated collaboration between multiple agents. This will be covered in a future article.**

MCP allows agents to reach out to other “endpoints” to find:

- Resources
- Prompts
- Tools
- [Sampling](https://modelcontextprotocol.io/specification/2025-06-18/client/sampling)

MCP supports [three transport](https://modelcontextprotocol.io/docs/concepts/transports) mechanisms:

- Standard I/O (**stdio**)
- Server-Sent Events (**SSE**) — *now StreamableHTTP*
- Custom *(user defined).*

As a network Engineer, I prefer **SSE** by far, so it’s easy to remotise, deploy and interconnect services across different machines.

Let’s see how I’ve added MCP to my Rails application.

- **Gems**. I’ve tried a few, but the only one which seemed to work well with SSE was fast-mcp .
- **Transport.** As I’ve said, **SSE** seems the best to use, if you work in a multi-language, multi-host environment.

***Note****. As of 2025–03–26 of the protocol, the **SSE transport is replaced by ****StreamableHTTP****.*

**Note**. You will probably get some frustration vibecoding this, since most information is from 2025 and models cutoff are likely before that. Unless you have **grounding** and/or live search capabilities, lean on my research or do your own!

### Enough theory, let’s see the code!

Let’s add the fast_mcp gem to the Gemfile:

```
# Gemfile
gem "fast-mcp", "~> 1.4"
```

Then, let’s add config/initializers/fast_mcp.rb as per gem docs:

```
FastMcp.mount_in_rails(
  Rails.application,
  name: Rails.application.class.module_parent_name.underscore.dasherize,
  version: '1.0.3',
  path_prefix: '/mcp',
  messages_route: 'messages', 
  sse_route: 'sse',
  allowed_origins: ALLOWED_HOSTS,
  localhost_only: false,
  allowed_ips: ALLOWED_IPS,
) do |server|
  Rails.application.config.after_initialize do
    # Automagically pulls all tools and resources, see below.
    server.register_tools(*ApplicationTool.descendants)
    server.register_resources(*ApplicationResource.descendants)
  end
end
```

In beautiful Rails style, you got now all Tools and Resources lined up under:

- [**app/tools/**](https://github.com/palladius/rails8-turbo-chat/tree/main/rubyllm_chat_app/app/tools)** **(for tools). They all inherit from ApplicationTool.
- [**app/resources/**](https://github.com/palladius/rails8-turbo-chat/tree/main/rubyllm_chat_app/app/tools)** **(for resources). They all inherit from ApplicationResource
- The two server.register_XXX ruby-style lines are telling the system to automatically load everything in those folders which inherits from those two classes. Find those two parent classes in their respective folders.

You can define ALLOWED_HOSTSand ALLOWED_IPS as you wish. You can start allowing all, and then restrict (harden) once it all works. If you need inspiration, check [my initializer](https://github.com/palladius/rails8-turbo-chat/blob/main/rubyllm_chat_app/config/initializers/aaa_ricc_hosts.rb).

If you have devise, you might want to disable it for /mcp/paths. To do so, try this in your initializer:

```
# remove auth from MCP paths
Rails.application.config.host_authorization = {
  exclude: ->(request) { request.path.include?("mcp") 
}
```

### My first Tool

***Note****: for this, I got inspiration from *[*this article by Siva Gollapalli*](https://learnitnow.medium.com/bridging-the-gap-connecting-python-ai-agents-to-ruby-apps-with-mcp-614977012399)*.*

Let’s write together our first tool: ListUsers

```
# app/tools/list_users.rb

class ListUsers < ApplicationTool
  description 'It list of users'

  def call
      User.all.map do |user|
          { id: user.id, name: user.name, email: user.email }
      end.to_json
  end
end
```

As you can see, this list all the users from the DB as an array of 3 relevant fields.

### My first Resource

This is basically identical, but it’s a different use. We’re creating a JSON Resource. This originally included the user’s Gemini API key (⚠️ dangerous ⚠️) and took me a while to configure the gemini key as if it were a password.

**Solution**: add this line to your initializer:

```
# config/initializers/gemini_api_key_should_be_private.rb
Devise::Models::Authenticatable::BLACKLIST_FOR_SERIALIZATION << :gemini_api_key
```

Thank you Devise! And now:

```
# app/resources/sample_resource.rb

class SampleResource < ApplicationResource
  uri 'examples/users'
  resource_name 'Users'
  description 'A user resource for demonstration (which Riccardo made safe, no trace of API Keys now)'
  mime_type 'application/json'

  def content
    JSON.generate(User.all.as_json)
  end
end
```

### Wait, how do I troubleshoot an MCP server?

Great question! The easiest way is to use this:

```
# Use npx or npm
npx @modelcontextprotocol/inspector
# Open browser at provided port, like http://localhost:62XX/ 
open http://localhost:62XX/
```

Now enter in the left side your information:

- Transport Type: **SSE**
- URL: [http://localhost:8080/mcp/sse](http://localhost:8080/mcp/sse) (or port 3000 or whatever you have)
- No authentication (for now).

### Recap

We’ve seen how to enrich an existing Ruby on Rails application by adding an MCP sparkle.

We’ve also seen how easy it’s to add a Tool or a Resource to our rails app which we can surface through .
