# Carlessian Article Authoring Skill

This skill provides a standardized checklist and guidelines for the "Carlessian" flow of writing, reviewing, and publishing articles (such as those posted on Medium, Dev.to, and ricc.rocks). 

When a user mentions they are ready to finalize or publish a "Carlessian article," apply the following checklists to ensure consistency, quality, and proper cross-posting metrics.

## 1. Post-Publication Sign-off Checklist
Ensure the following tasks are executed before or immediately after publishing an article:

- [ ] **Tone & Style Unit Test**: Verify the flow is fun, energetic, and written in Riccardo's relatable developer advocate style.
- [ ] **Readability & Grammar**: Review the entire draft to ensure it reads well, flows naturally, and has no typos.
- [ ] **AI Auditor / Vale & Gunning Fog**: Verify Gunning Fog Index and Slop Score (use tools to ensure zero filler words and professional readability).
- [ ] **Asset Verification**: Ensure all mentioned external assets (YouTube videos, GitHub repositories, Mermaid `.dot` graphs, dynamic PNGs) are listed, built properly, and function.
- [ ] **Publish Draft**: Publish the draft on target platforms (e.g., Medium, Dev.to).
- [ ] **Canonical URLs**: Ensure the canonicalURL from the primary publication platform is added back to the local markdown frontmatter.
- [ ] **Publicize**: Create social media posts (LinkedIn, Twitter) and update with canonical links.
- [ ] **Community Share**: Paste the announcement snippet into relevant developer communities (using `:medium:`, `:linkedin:`, `:x-twitter:`, `:bluesky-logosvg:` emojis).
- [ ] **UTM Tags**: Add appropriate UTM tags to supported outbound links to track traffic (`?utm_medium=external&utm_source=blog`).
- [ ] **Ask for publication**: Request publication in relevant community publications.
- [ ] **Close Ticket**: Close the tracking issue in your project management tool (Jira, GitHub Issues, etc.).
- [ ] **External Reviewer**: Get approval and record the sign-off (Approved by / Date).

## 2. Directory Structure and Best Practices
When working on a Carlessian article, maintain this directory structure:
* `ARTICLE.md` - Main content and frontmatter
* `TODO.md` - Active working checklist
* `CHANGELOG.md` - Tracking incremental changes
* `VERSION` - Version string (e.g., 1.2)
* `SOURCES.md` - Reference materials and CTAs
* `assets/` and `images/` - Visual assets, dynamically generated graphs via `just deploy` or `build_dots.py`

Always rely on `just build` or `just deploy` for testing the static compilation pipeline before publishing.
